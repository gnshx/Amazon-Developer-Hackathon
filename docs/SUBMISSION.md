# Warrant: Devpost Submission & Hackathon Strategy

**Hackathon:** Amazon Developer Hackathon (Alexa+ Track)  
**Submission Cutoff:** 23 October 2026, 11:59 PM IST (Official deadline: 24 Oct, 12:30 AM IST)  
**License Strategy:** Dual-repository open-source architecture  

---

## 1. Project Title & Taglines

- **Project Title:** Warrant — A Trust Gateway for Voice Agents
- **Elevator Pitch (1 sentence):** An open-source MCP trust gateway that makes voice agent actions provably safe through scoped grants, cryptographic approval binding, automatic saga rollback, and an adversarial attack scorecard.
- **Track Selection:** Alexa+ Track
- **Mini-Challenge Selections:**
  1. **Additional Open Source Project Mini-Challenge:** `warrant-siege` is an independent, standalone open-source testing CLI (MIT License) that attacks any MCP server with 8 standard adversarial scenarios and generates an automated safety scorecard.
  2. **AWS Builder Mini-Challenge:** Native integration with Amazon Bedrock Converse API (`@aws-sdk/client-bedrock-runtime`) for autonomous tool calling, with detailed developer feedback in `docs/FRICTION_LOG.md`.
  3. **Judging Bonus (Up to 10%):** Comprehensive developer friction log documenting real-world friction and actionable recommendations for AWS Bedrock and MCP SDKs.

---

## 2. Scope Honesty & Transparency Statement

> **Mandatory Transparency Disclosure for Judges:**  
> The genuine Alexa+ developer environment is restricted to select partners. To adhere to hackathon transparency guidelines, this project uses:
> 1. **Simulated Alexa+ Client:** A Next.js 14 web application simulating voice interaction, approval cards, and live tool traces.
> 2. **Simulated Mock Providers:** Standalone Hotel, Train, and Restaurant services with fault injection endpoints (`TIMEOUT`, `DECLINE`, `DISCONNECT`).
> 
> Both are explicitly labelled as simulated in code, documentation, and the demo video. The MCP gateway (`warrant-gateway`) and adversarial test harness (`warrant-siege`) communicate over actual network protocols (Streamable HTTP, JSON-RPC 2.0).

## 4. Workstream Cut Order (If Behind Schedule)

If time pressure increases, cuts are executed in this strict priority order:
1. **Microphone Voice Input:** Fallback to typed voice simulation with real speech synthesis output (`spoken_summary`).
2. **Polished Approval UI:** Use standard functional phone web view over complex animations.
3. **End-to-End Agent Attacks:** Keep deterministic scripted protocol-level attacks in the harness; reserve agent-in-the-loop attacks for stretch runs.
4. **Cloud Hosting:** Keep local demo via Docker Compose / `npm run dev`.

**NEVER CUT:**
- Automatic Saga Rollback ($I_4$)
- Cryptographic Parameter-Hash Approval Binding ($I_3$)
- Absolute Spend Cap Enforcement ($I_2$)
- Standalone `warrant-siege` Scorecard Generator ($I_1 - I_8$)
